# 🛡️ Smart Push Monitor (SRE Edition)

Продвинутый Bash-скрипт для мониторинга состояния VPN-узлов с интеграцией в **Uptime Kuma** (Push-тип). Скрипт разработан для системных администраторов, управляющих распределенной сетью Linux VPS.

В отличие от стандартных методов, этот инструмент имитирует поведение реального пользователя, различает типы сетевых сбоев и реализует логику «самолечения» сервисов.

## 🚀 Основные возможности

*   **Гибридная проверка (L3-L7):** Контроль не только наличия процесса, но и реальной проходимости трафика через TCP/UDP и валидности TLS-рукопожатия.
*   **Умное самолечение (Auto-Remediation):** Автоматический перезапуск Docker-контейнеров при достижении заданного порога ошибок (например, при зависании Xray/Hysteria).
*   **DPI-Friendly:** Специальный режим гибридной проверки для протокола Reality. Основное время выполняется легкий L4-чек, и лишь раз в несколько циклов — полный TLS-handshake, что снижает риск детектирования системами глубокой инспекции трафика.
*   **Протокольная гибкость:** Полная поддержка TCP (VLESS/Reality) и UDP (Hysteria 2/QUIC).
*   **Ansible-Ready:** Архитектура скрипта оптимизирована для массовой раскатки через Ansible Semaphore на неограниченное количество нод.

## 🛠 Техническая логика

Каждую минуту скрипт выполняет каскад проверок:

1.  **Internet Check:** Пинг публичных DNS. Если связи нет — статус `No_internet`. Это исключает ложные алерты при сбоях самого провайдера сервера.
2.  **Bridge Check:** Проверка доступности удаленного «выходного» моста (например, связи между РФ и Германией).
3.  **Container Check:** Проверка статуса контейнера через `docker inspect`.
4.  **L4/L7 Hybrid:** 
    *   **L4:** Быстрая проверка доступности порта.
    *   **L7:** Глубокое TLS-рукопожатие (OpenSSL + Curl fallback) для подтверждения работоспособности прокси-протокола.

## 📖 Руководство по установке

### 1. Подготовка
Убедитесь, что на целевых серверах установлены необходимые утилиты:

```bash
apt update && apt install -y jq netcat-openbsd curl docker.io
```
2. Настройка инвентаря (Ansible/Semaphore)
Добавьте переменные для ваших хостов в YAML-инвентарь:
```bash
ru-mow-09.infra:
  ansible_host: 80.66.81.130
  kuma_push_url: "[https://kuma.example.com/api/push/token?v=1](https://kuma.example.com/api/push/token?v=1)"
  vpn_port: 443
  vpn_proto: "tcp"           # tcp для Reality, udp для Hysteria
  sni: "google.com"
  bridge_ip: "31.56.39.237"  # Опционально: IP моста
  bridge_port: 443
  bridge_port_proto: "udp"   # Протокол моста
```

3. Деплой
Используйте плейбук для автоматического копирования шаблона и настройки Cron:

```bash
- name: Deploy Smart Monitor
  hosts: vpn_nodes
  become: yes
  tasks:
    - name: Upload script from template
      template:
        src: smart_push.sh.j2
        dest: /opt/smart_push.sh
        mode: '0755'

    - name: Setup Cron Job (every minute)
      cron:
        name: "Run Smart Push Monitor"
        minute: "*"
        job: "/opt/smart_push.sh"
```
## 📊 Интерпретация статусов

В панели Uptime Kuma вы будете видеть детальные причины сбоев:

| Сообщение | Описание проблемы | Действие скрипта |
| :--- | :--- | :--- |
| **OK** | Все системы работают штатно | Пинг (Up) |
| **No_internet** | Локальная проблема со связью на сервере | Только лог |
| **Bridge_down** | Недоступен выходной узел | Только лог |
| **Container_dead** | Docker-контейнер упал или остановлен | Рестарт (после 3 попыток) |
| **Port_unreachable** | Сервис не слушает порт | Рестарт (после 3 попыток) |
| **TLS_failed** | Ошибка рукопожатия | Рестарт (после 3 попыток) |

## ⚠️ Важные примечания

* **Cooldown:** После автоматического рестарта скрипт выжидает 5 минут (период охлаждения), прежде чем предпринимать новые попытки исправления.
* **Locks:** Используется `flock` для защиты от параллельного запуска нескольких копий скрипта при зависании сетевых запросов.
